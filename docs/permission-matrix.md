# 权限矩阵

> 版本：1.6（临时凭证取消到期限制）
> 状态：业务方已确认角色、数据范围、字段访问及 TODO-31/58 凭证规则。
> 本矩阵区分学生、导师和管理员业务权限。总管理员仍使用 `ADMIN` 角色，但拥有全部已登记管理员业务能力和全系统学院/批次范围，并额外负责管理管理员账号；不允许其冒充学生/导师或绕过业务规则与审计。

## 1. 权限标记

- **允许：** 该角色在身份、时间和业务状态校验通过后可执行。
- **本人：** 仅限本人账号、资料、志愿或结果。
- **当前申请：** 仅限当前轮投给该导师的学生申请。
- **授权范围：** 仅限管理员被授权的批次/学院范围。
- **禁止：** 普通业务流程不得执行。

> 授权范围与字段级细节的决策依据见 [待确认事项登记表](todo-register.md)；学生资料字段的逐项可见性另见第 5 节。

矩阵中的“管理员”列表示普通管理员的学院/批次业务权限。总管理员拥有所有管理员业务能力和全系统范围；管理员账号目录查询、创建/重置及其他 ADMIN 账号的业务能力授予/撤销仅由总管理员执行。两者都必须遵守对象状态、名额、时间和审计规则。

服务端对每次请求执行权限和对象范围校验；前端隐藏按钮不能替代后端授权。

## 3. 管理员角色与范围

普通 ADMIN 仅在获授学院/批次范围内管理业务。系统设一位总管理员，仍属于 `ADMIN` 角色，但拥有全部已登记管理员业务能力和全系统学院/批次范围；同时负责管理员账户生命周期及为其他 ADMIN 账号授予/撤销普通业务能力。该身份不会切换为学生/导师角色，也不会绕过对象状态、名额、时间和审计校验。管理员账户的创建/重置仅由总管理员执行并全程审计，凭证为随机、无到期时间的一次性临时凭证，仅一次性展示并由管理员线下转达；首次登录强制改密。权限点包括：

- **批次管理：** 创建、发布、暂停和结束批次。
- **人员管理：** 创建账号、维护导入名单和人员状态。
- **规则管理：** 配置资格、志愿数、轮次时间、导师名额和补选时间。
- **结果管理：** 查看匹配结果并处理授权异常。
- **数据导出：** 导出名单与统计。
- **审计查看：** 查询敏感操作记录。

**已确定：** 总管理员拥有全系统管理员业务权限，另负责管理管理员账户；不另设学生/导师身份冒充能力。关系例外仍须按对象状态、名额、范围和审计规则办理。**BR-10（已确认）：** 管理员账户的创建/重置仅由总管理员执行并全程审计；凭证为随机、无到期时间的一次性临时凭证，仅一次性展示并由管理员线下转达，首次登录强制改密，不通过邮件或短信发送（TODO-31）。**应急恢复（TODO-24）：** 总管理员账户仅设一个，须由学校主管部门线下核验身份后执行凭证重置或账户移交，双人复核并全程留痕；该流程不改变总管理员的系统级业务权限。

**管理员业务授权（TODO-52 至 TODO-57，2026-10-04 已确认）：** 仅总管理员可以向其他 ADMIN 账号授予或撤销普通业务能力，且须明确学院/可选批次范围并保留完整审计。`COLLEGE_ADMIN` 必须覆盖完整学院，负责人员、专业、资格和导入；不接受批次级缩小。新增 `BATCH_MANAGER`，可授予完整学院或指定批次范围，用于批次配置、导师名额及发布/启动；批次级授权不得创建新批次。`BATCH_AUDIT` 保持只读。常规 API 不得授予、转移或撤销 `ADMIN_ACCOUNT_MANAGER`；仅系统初始化或 TODO-24 应急恢复流程可设置该能力。年度资格保留历史且每人每年仅一条当前记录；导入逐行报告并只在首次响应返回新凭证。

`BATCH_AUDIT` 的批次只读范围包括获授批次目录、详情、阶段与导师名额配置状态、统计；不得创建/修改批次、配置排期/名额、执行发布/启动/暂停/恢复/取消/归档或调整补选导师。批次级授权只可查看指定批次，学院级授权可查看该学院批次。

**人员初始密码（TODO-58，2026-10-05 已确认）：** 管理员手工创建或通过名单导入新建学生/导师账号时，初始密码分别取学号/工号末尾六位；编号不足六位时使用完整编号。服务端仅以安全哈希保存；凭证不设到期时间、仅可成功使用一次，首次成功响应展示一次且首次登录强制改密；导入历史和幂等重放不返回明文。管理员账号仍使用随机凭证，但同样不设到期时间（TODO-31）。

**总管理员全系统权限（TODO-56，2026-10-03 已确认）：** 总管理员对所有已登记管理员业务能力享有隐式有效授权，范围覆盖所有启用学院和批次，无须逐项新增授权记录。该规则不授予 `ROLE_STUDENT` / `ROLE_TEACHER`，也不跳过业务状态、对象归属、名额、截止时间或审计检查。

## 4. 字段级访问原则

1. 学生仅查看本人敏感信息和本人互选状态。
2. 导师只能查看当前批次中申请过本人的学生资料，字段限于姓名、学号、专业、学位类型、个人简介和简历；其他学生不得查看他人资料、成绩或简历。
3. 学生简历只能经受控鉴权接口访问，不提供免鉴权的公开下载地址。管理员按授权范围查看。
4. 匹配记录、申请记录和关键审计记录长期保留；简历附件保留至学生毕业后 5 年（以学校数据管理要求为准），期间不自动删除历史附件。
5. 管理员按任务最小化查看个人资料；结果导出应限字段、限范围并留痕。
6. 导师公开资料需区分公开字段和内部维护字段；学生可见导师「是否可填报」布尔值，不显示具体剩余名额，目录提供研究方向、姓名或工号、「是否可填报」三项筛选（TODO-28）；导师联系方式不公开。
7. 角色或组织范围变更应立即影响后续请求权限；已导出的数据不能由权限系统收回，因此导出前需再次授权。
8. 简历留存截止根据经学校确认的毕业日期计算；授权管理员维护毕业日期及变更记录。日期缺失或未确认时不自动删除简历。
9. 学生目录的“是否可填报”结合该学生的专业和学位类型判断；查看导师公开范围不赋予查看其他学生身份信息的权限。范围配置与导师介绍的公开审核分开表达，不能由 TODO-P07 自动推定可报范围审批政策。
10. 填报开始后管理员按 TODO-48 更正学生身份时，如已有匹配关系须撤销并释放名额，该生跳过剩余常规轮次、变为 `UNMATCHED` 并等待补选；不得由导师或学生自行撤销关系。无补选窗口等低概率边界暂缓，本期不处理（TODO-49）。
