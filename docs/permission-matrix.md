# 权限矩阵

> 版本：0.2（详细设计草案）  
> 本矩阵区分学生、导师、计算机学院管理员和唯一总管理员。总管理员具备管理员权限，并负责管理管理员账户及审批名额/已锁定关系例外；不另设校级管理员。

## 1. 权限标记

- **允许：** 该角色在身份、时间和业务状态校验通过后可执行。
- **本人：** 仅限本人账号、资料、志愿或结果。
- **当前申请：** 仅限当前轮投给该导师的学生申请。
- **授权范围：** 仅限管理员被授权的批次/学院范围。
- **TODO：** 原始需求无法确认授权范围或字段细节。
- **禁止：** 普通业务流程不得执行。

矩阵中的“管理员”列覆盖普通计算机学院管理员与唯一总管理员；标注“仅总管理员”的操作不授予普通管理员。总管理员继承管理员权限，额外权限见第 3 节。

服务端对每次请求执行权限和对象范围校验；前端隐藏按钮不能替代后端授权。

## 3. 管理员角色与范围

当前由计算机学院管理员管理本学院业务。系统不另设校级管理员，设一位总管理员；总管理员具备管理员业务权限，可管理管理员账户，并审批名额和已锁定关系的例外调整。管理员账号如何创建、重置和审计仍需细化。权限点包括：

- **批次管理：** 创建、发布、暂停和结束批次。
- **人员管理：** 创建账号、维护导入名单和人员状态。
- **规则管理：** 配置资格、志愿数、轮次时间、导师名额和补选时间。
- **结果管理：** 查看匹配结果并处理授权异常。
- **数据导出：** 导出名单与统计。
- **审计查看：** 查询敏感操作记录。

**已确定：** 不另设校级管理员；仅设一位总管理员，总管理员在管理员权限基础上可以管理管理员账户。具体关系例外由总管理员审批并执行，过程留痕。**TODO-BR-10：** 管理员账户的创建、重置、凭证交付和审计流程。

## 4. 字段级访问原则

1. 学生仅查看本人敏感信息和本人互选状态。
2. 导师只能查看当前批次中申请过本人的学生资料，字段限于姓名、学号、专业、个人简介和简历；其他学生不得查看他人资料、成绩或简历。
3. 学生简历只能经受控鉴权接口访问，不提供免鉴权的公开下载地址。管理员按授权范围查看。
4. 匹配记录、申请记录和关键审计记录长期保留；简历附件的具体保留期依学校数据管理要求确定，未确认前不自动删除历史附件。
5. 管理员按任务最小化查看个人资料；结果导出应限字段、限范围并留痕。
6. 导师公开资料需区分公开字段和内部维护字段；学生是否可见导师名额、联系方式等由业务方配置。
7. 角色或组织范围变更应立即影响后续请求权限；已导出的数据不能由权限系统收回，因此导出前需再次授权。
