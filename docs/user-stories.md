# 用户故事与验收要点

> 版本：1.0（已确认验收基线）  
> 状态：业务方确认按当前内容定案。验收要点说明业务预期，不代表功能已实现或已测试；已确认规则见 [待确认事项登记表](todo-register.md)。

## 1. 学生

### US-STU-01 查看导师

**作为**符合批次条件的学生，**我希望**按组织或研究方向浏览导师并查看公开资料，**以便**填报志愿前了解导师。

**验收要点：**
- 只显示当前批次可选且公开的导师。
- 目录及详情展示允许学位类型和专业；“是否可填报”结合本人专业/学位判断，不同学生对同一导师的结果可能不同。类型或专业任一不符不能提交该导师。
- 导师公开字段来自经确认的数据；学生不能查看其他学生信息。
- 导师公开资料字段经管理员审核后公开；目录提供研究方向、姓名或工号、「是否可填报」三项筛选；学生可见导师是否可填报（布尔值），不显示具体剩余名额（`TODO-28`）。

### US-STU-02 一次性提交有序志愿

**作为**符合资格的学生，**我希望**在一次提交中选择一至三位不同导师并标明优先级，**以便**按意愿参加三轮处理。

**验收要点：**
- 每个志愿属于当前批次，导师不能重复，优先级明确为 1、2、3。
- 提交前学生须核对并确认本人显示的专业、学位类型无误；确认关联当时的身份分类版本。
- 每个导师均允许学生本人的学位类型与专业；服务端检查全部志愿，任一项不符拒绝完整提交，不保存半份版本。
- 第 1 志愿只供第 1 轮处理，第 2 志愿只供第 2 轮处理，第 3 志愿只供第 3 轮处理。
- 提交后学生能查看已保存的顺序和提交状态。
- 填报截止前可以修改或撤回；截止后志愿锁定。
- 填报期内导师不可见；进入对应轮后仅可见投向本人该顺位的申请，看不到其他志愿。

### US-STU-03 查看每轮进度

**作为**已提交志愿的学生，**我希望**看到当前处理轮次和匹配状态，**以便**知道是否会进入后续轮次。

**验收要点：**
- 未匹配学生按当前顺序等待对应志愿轮次。
- 当前轮录取成功后立即显示 `MATCHED` 和导师信息；后续常规轮次不再处理该学生。
- 三轮结束仍未匹配时显示 `UNMATCHED`。
- 批次启动时若前序阶段已错过，当前轮只处理仍未匹配且已锁定当前顺位志愿的学生；错过的已填志愿显示为因时间跳过，不显示为导师不录取；没有尚未错过的志愿者显示 `UNMATCHED`。
- 未提交志愿者在填报截止时置为 `UNMATCHED` 且可参加补选；未填满三项志愿者在其最后一个已填志愿轮结束仍未匹配时显示 `UNMATCHED`，原因记录为 `PREFERENCE_EXHAUSTED` 并附实际末轮/顺位，计入正常志愿流程未匹配统计。轮次进行中只显示「待处理／已处理」，不公布导师的录取或不录取结论，轮次关闭后统一公布该轮结果；学生始终可见本人当前匹配状态（`TODO-29`）。导师不填写不录取原因；学生不得查看他人信息。

### US-STU-04 参加管理员开放的补选

**作为**三轮后处于 `UNMATCHED` 的学生，**我希望**在管理员设定的补选时段内查看并办理补选，**以便**继续获得导师选择机会。

**验收要点：**
- 补选入口只在开放时间内显示并接受操作。
- 已匹配学生不能通过补选改变已锁定关系。
- 仅当前为 `UNMATCHED` 的学生可参加。
- 只有有剩余名额且经管理员允许参加补选的导师可被选择。
- 补选沿用本批次冻结的允许学位类型和专业，提交与录取都校验两项条件，不因进入补选放宽。
- 学生每次只申请一位导师，同一时刻最多一条待处理申请；导师不录取后，学生可在窗口内申请其他符合条件的导师。
- 导师逐项录取或不录取，不排序；录取成功立即锁定关系、扣减名额、创建最终 `MatchingResult`，学生转为 `MATCHED` 并退出补选。
- 不录取后申请状态为 `REJECTED`，学生仍为 `UNMATCHED`；补选关闭时仍未匹配者继续为 `UNMATCHED`。
- 批次取消时，待处理或处理中的补选申请转为 `CANCELLED_BY_BATCH`。
- 补选窗口关闭后不得重新开放；结束时待处理申请按不录取结案（`REJECTED`），批次自动进入 `COMPLETED`；从未开启补选的批次三轮关闭后即可完成。

### US-STU-05 维护本人资料和简历

**作为**学生，**我希望**维护允许编辑的本人资料并提交简历，**以便**当前批次中申请过我的导师了解必要信息。

**验收要点：**
- 学生只能维护本人资料；导师和管理员只能按已授权范围访问。
- 简历通过受控文件访问方式提供，不生成免鉴权的公开下载链接。
- 可编辑字段为个人简介、简历附件、联系方式（姓名/学号只读）；专业和学位类型由管理员导入/纠错，学生只能查看。简历格式限 PDF、单文件 ≤10MB。
- 学生提交志愿前需核对所显示的专业、学位类型并确认；发现错误时向管理员提交更正申请，身份分类不开放自行编辑。管理员更正后，学生须重新核对、确认新版本。
- 该批次申请进入待处理时，导师看到姓名、学号、专业、学位类型、个人简介及当时的简历版本；不含联系方式和成绩。历史申请保留对应资料快照。
## 2. 导师

### US-TCH-01 维护公开资料

**作为**导师，**我希望**维护自己的公开介绍和研究方向，**以便**学生填报前了解指导信息。

**验收要点：**
- 导师只能编辑本人获准编辑的资料字段。
- 导师可维护本人研究方向、个人简介等公开字段；公开字段经管理员审核后对系统内学生可见。

### US-TCH-02 查看当前轮申请并逐项处理

**作为**导师，**我希望**查看当前轮投给我的学生并逐项选择录取或不录取，**以便**依据本轮意向处理申请。

**验收要点：**
- 第 1/2/3 轮分别只出现对应志愿顺位的学生。
- 之前已匹配的学生不再出现于后续轮次队列。
- 导师只能查看授权范围内的申请，不得检索无关学生。
- 申请进入待处理时形成的资料快照限姓名、学号、专业、学位类型、个人简介和当时的简历版本；不含联系方式和成绩。轮次重开后的处理周期建立新的快照，但仍须通过当前访问授权。
- 可查看当前批次中申请过本人的学生资料，包括姓名、学号、专业、学位类型、个人简介和简历；不得浏览无业务关系学生资料。
- 学生简历仅通过受控鉴权接口访问，不提供公开下载地址。
- 填报期内导师不可见；进入对应轮后仅可见投向本人该顺位的申请，看不到其他志愿。
- 导师不对申请学生排序；本轮结束时未处理申请按不录取处理。

### US-TCH-03 在剩余名额内录取

**作为**导师，**我希望**在每轮剩余名额范围内录取学生，**以便**形成有效的师生关系。

**验收要点：**
- 系统显示本批次当前剩余名额，已被前序轮次录取的学生计入已用名额。
- 每次录取都重新校验学生未匹配、导师仍有名额，以及学位类型和专业均符合本批次冻结范围。
- 成功后立即锁定关系，学生状态变为 `MATCHED` 并退出后续轮次。
- 并发录取不得造成超额或学生重复匹配。
- 导师可逐项选择录取或不录取，不进行排序；本轮结束时未处理申请全部按不录取处理。
- 不录取无需填写原因；系统通知学生处理结果。支持批量处理。
- 批量录取时若选中人数超过剩余名额，按确定性顺序（该顺位志愿最终锁定版本的提交时间升序，同一时间按学号升序）依次录取至名额用尽；因名额不足未录取的余项结案为 `NOT_ADMITTED`，返回逐项成功/失败明细并提示“名额不足，部分未录取”；通知以站内通知为准，失败留痕（`TODO-27`）。

### US-TCH-04 查看结果和名额

**作为**导师，**我希望**查看本人已录取学生、名额使用和剩余情况，**以便**跟进本批次。

**验收要点：**
- 只展示本人有权访问的批次与关系。
- 导师不能自行调整名额或取消锁定关系。
- 导师仅查看投向本人且属当前顺位的申请，不查看未匹配申请的最终状态；导出限本人当前/已处理申请范围。

### US-TCH-05 设置本批次可报范围

**作为**导师，**我希望**选择本批次接受的学生学位类型和专业，**以便**符合范围的学生向我填报。

**验收要点：**

- 类型选择支持仅学硕、仅专硕、两者均可；允许专业可选择多个，按专业目录引用保存。
- 只能维护本人在相应批次的范围；填报开始时冻结，之后普通编辑被拒绝，其他批次范围不受影响。
- 第一、第二、第三志愿和补选沿用该批次冻结范围，不按轮次重新选择。
- 例如仅学硕 + 专业 A/B 时，学硕/专业 A 符合范围；专硕/专业 A、学硕/专业 C 均不能申请。
- 无需管理员审核。参与导师范围配置不完整时系统按全勾选默认，即两类学位和全部专业都允许；填报开始时冻结该默认范围。管理员维护专业目录。

## 3. 管理员

### US-ADM-01 创建账号和维护人员

**作为**管理员，**我希望**创建学生与导师账号并维护其组织和资格信息，**以便**为批次准备准确名单。

**验收要点：**
- 首期账号由管理员创建，不开放自行注册。
- 系统提示重复账号、缺失字段和不符合格式的数据。
- 学生名单包含专业和学位类型（学硕或专硕）；管理员依据学校信息导入/纠错，变更记录前后值、依据、操作者和时间。学生不可自行修改；正式专业清单由管理员维护（TODO-47）。
- 学生在填报前检查身份信息；错误向管理员提交修改。填报开始后纠错时，若已录取则管理员撤销关系并释放导师名额；学生转为 `UNMATCHED`，跳过剩余常规轮次等待补选，并保留志愿/关系/名额审计。
- 使用学号/工号作为登录标识；系统提供随机的一次性临时凭证或受控的首次设置流程，首次使用时必须设置个人密码，完成前不能办理互选业务。不得使用可由学号/工号推算的临时密码。
- 忘记密码时管理员可重置为新的临时密码，并要求用户再次修改；停用账号后拒绝登录及后续业务请求，但保留历史数据。
- 密码以安全哈希保存，不存明文。
- 总管理员是计算机学院管理员之一，业务权限与其他管理员相同，仅额外拥有管理管理员账户的权限；不另设校级管理员。
- 管理员账户创建/重置仅由总管理员执行并全程审计；临时凭证为随机一次性凭证、有效期 72 小时、仅一次性展示并由管理员线下转达，首次登录强制改密，不通过邮件或短信发送（`TODO-31`）。人员名单采用 Excel/CSV 模板导入并手工维护，学生以学号、导师以工号为唯一标识，导入须生成批次记录与错误报告（重复、缺失、格式不符）（`TODO-30`）。

### US-ADM-02 配置和发布批次

**作为**有权限的管理员，**我希望**配置批次范围、填报时间、志愿限制、导师名额，并维护经确认的阶段安排，**以便**按确认后的规则组织互选。

**验收要点：**
- 发布前可以预览配置，必需配置缺失时不能发布。
- 查看导师本批次允许学位类型和专业；无需审核，配置不完整按两类学位和全部专业全选；填报开始时冻结范围并保留版本。跳过填报阶段启动时如何冻结及无补选窗口时身份纠错如何办理待 TODO-49。
- 志愿数为 1–3 且导师不重复，规则快照可供事后核对。
- 管理员在发布前决定是否安排补选；安排时须配置补选开放时间。批次发布后不得新增补选安排；补选时间和安排仅可在窗口关闭前调整。窗口关闭时待处理申请结案，批次自动进入 `COMPLETED`（TODO-39）。
- 填报窗口开放时冻结合格学生名单和统计分母；包含未提交志愿者，不包含已在同学年其他批次锁定匹配者。后续资格/账号变化不自动回算；名单更正留审计。
- 管理员手动启动已发布且通过校验的批次；开始时按当前时间进入相应阶段，早于填报窗口时保持 `ACTIVE` 并等待填报开始。错过填报窗口后不能补交志愿；已错过的轮次不补办，当前轮只处理当前顺位已锁定志愿，之后轮次仍按对应优先级处理。所有志愿轮次都已错过的学生置为 `UNMATCHED`。常规轮次后续按配置时间自动切换。
- 同一学年、同一学院最多一个 `SCHEDULED`、`ACTIVE` 或 `PAUSED` 批次；前批次完成、归档或取消后可创建后续批次，首期不支持并行运行批次。追加批次创建时记录原因。
- 暂停后学生和导师停止办理，当前阶段剩余时长冻结；恢复后当前及所有未开始阶段整体平移累计暂停时长，已提交数据及锁定关系保留。
- 取消后停止后续流程并保留历史数据和审计记录，不物理删除；已锁定关系不自动撤销并标记来源批次已取消；待处理或处理中的申请转为 `CANCELLED_BY_BATCH`。
- 若启动时已错过全部阶段，禁止启动；管理员可撤回发布（`SCHEDULED → DRAFT`）重新配置时间后再次发布，或直接取消批次，撤回发布须记录审计。
- 从未开启补选的批次三轮关闭后即可完成；补选关闭时待处理申请按不录取结案；批次取消后未匹配学生复用 `UNMATCHED`；不引入“尚未正式生效”关系状态（录取即 `LOCKED`）。

### US-ADM-03 监控三轮进度

**作为**管理员，**我希望**看到各轮待处理、已录取、未匹配和名额使用情况，**以便**协调本批次处理进度。

**验收要点：**
- 可按批次和授权组织查看汇总数据。
- 三轮按序推进，匹配成功人数占用导师名额。
- 第三轮结束后尚未匹配的学生被标记为 `UNMATCHED`。
- 管理员可在轮次关闭前延期，设置新截止时间并相应顺延后续轮次；记录前后截止时间、操作者、时间和原因。轮次关闭后不能直接延期，须通过单独的重开操作并审计。
- 已关闭轮次仅可由管理员重开，且须满足：批次已暂停，下一轮尚未产生任何处理动作；重开时重算后续阶段时间，不影响已锁定/已录取，未处理回 `IN_REVIEW`。名额调整后不得低于已锁定人数。统计口径见本文件 US-ADM-06（`TODO-32`）。
- 重开只恢复系统因截止而自动结案的申请；明确不录取和批量名额不足结案不恢复。原自动结案保留；仅因自动结案推进的学生退回本轮处理前状态，下游无人处理的等待申请标记为被重开取代。

### US-ADM-04 开启补选

**作为**管理员，**我希望**设定并开启补选时间，**以便**为未匹配学生提供经批准的后续办理窗口。

**验收要点：**
- 补选开放时间按批次发布前配置生效；开放时段结束后不得继续提交。
- 开启补选不会自动重跑第一至第三轮。
- 补选候选限 `UNMATCHED` 学生和有剩余名额且获准参加的导师。
- 学生一条待处理补选申请被拒后，可以申请其他符合条件的导师；一旦录取即锁定并退出补选。
- 批次取消时待处理或处理中的补选申请转为 `CANCELLED_BY_BATCH`。
- 批次完成后不可追加补选安排。补选窗口关闭即批次完成，关闭后不得重开；任何安排调整须在窗口关闭前完成（TODO-39）。
- 关闭时待处理申请按不录取结案（`REJECTED`）；从未开启补选的批次三轮关闭后即可完成。

### US-ADM-05 处理例外并审计

**作为**有授权的管理员，**我希望**处理人员数据错误或业务例外并记录原因，**以便**保持结果可追溯。

**验收要点：**
- 重要变更记录操作者、时间、对象、前后值和原因。
- 例外调整不静默覆盖历史关系或志愿。
